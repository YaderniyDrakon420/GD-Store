# GD Store frontend

React + Vite. Данные и учётные записи загружаются из Django; автономного режима с localStorage больше нет.

## Запуск

Сначала запустите Django по инструкции в корневом README. Нужен Node.js 22.12+.

```powershell
npm.cmd ci
npm.cmd run dev
```

Vite проксирует `/api` и `/media` на `http://127.0.0.1:8000`. Для другого адреса задайте переменную окружения `API_PROXY_TARGET` до запуска. Браузер обращается к тому же адресу Vite; сессия Django хранится в HttpOnly-cookie.

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
```

`src/server/api.mjs` отправляет запросы с CSRF и ключами идемпотентности, `src/server/context.jsx` синхронизирует серверное состояние, `src/server/catalog.mjs` содержит текущий каталог из API. Страницы `src/studio` сохраняют исходные CSS-классы и оформление.

Старые `src/demo/*.mjs` оставлены для тестовых фикстур и чистых вспомогательных функций. Страницы больше не вызывают локальный reducer и не сохраняют профили в браузере. `src/demo/context.jsx` — совместимый экспорт нового серверного провайдера.

Сборку `dist` можно размещать на отдельном хостинге: либо проксировать `/api` и `/media` на Django, либо указать `VITE_API_BASE_URL=https://api.example.com/api/v1/` перед сборкой и настроить CORS/CSRF на бэке. Пример переменных — в `.env.example`; подробности и ограничения сторонних cookies — в `../docs/SPLIT-HOSTING.md`. `vite preview` сам по себе предназначен только для просмотра сборки и не заменяет сервер приложений.

Опрос сервера каждые 5 секунд обновляет присутствие и индикаторы друзей. Возврат на вкладку и восстановление соединения вызывают немедленное обновление. Состояние онлайн хранится в БД Django и истекает без подтверждений.

`npm run test:integration:split` проверяет React с настоящим Django на другом origin. Нужен `PYTHON`, указывающий на интерпретатор с серверными зависимостями; тест использует временную базу.
