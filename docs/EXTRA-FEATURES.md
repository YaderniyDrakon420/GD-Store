# Дополнения GD Store

Дата: 22 сентября 2026. Основа: `4d7a4be`. Это продолжение проверки из `FINAL-AUDIT.md`.

## Что сделано

1. **Форма пополнения.** На странице кошелька выбирается сумма и вводятся номер тестовой карты, имя, срок действия и CVC. Достаточно любых непустых значений; формат, срок и номер не проверяются. Данные карты существуют только в состоянии формы, после успеха очищаются и не передаются Django. Запрос содержит только действие и сумму. Начисление требует включённого `PAYMENT_TEST_MODE`, сохраняется в серверном журнале и защищено от повтора запроса. Пополнение не начисляет баллы.
2. **Галерея и требования.** Использованы существующие модели `Screenshot` и `SystemRequirement`, к последней добавлено поле `notes`. Сортировка галереи учитывает `Order`, затем ID; миниатюры, стрелки и модальное окно используют существующий стиль. Добавлены девять официальных изображений и сведения для GTA V Enhanced, CS2, Dota 2. При повторном наполнении каталога ручные правки сохраняются.
3. **История просмотров.** Сервер хранит до 12 уникальных опубликованных игр на аккаунт. Повторный просмотр поднимает игру, очистка сохраняется в БД. Ни гостям, ни другому пользователю история через snapshot не выдаётся.
4. **Чаты.** Поиск без учёта регистра работает по загруженным сообщениям выбранного диалога. Закрепления сохраняются отдельной моделью, общие для двух собеседников; максимум 10, менять их могут только участники, оставшиеся друзьями. Изменение исходного сообщения сохраняет закрепление, удаление убирает его. Права администратора не открывают закрепления чужого диалога через API.
5. **Релиз предзаказа.** Сохранение опубликованной игры без флажка предзаказа уведомляет действующих владельцев оплаченного предзаказа. Подарок направляет уведомление получателю, возврат исключает заказ. Уникальная запись доставки предотвращает повтор даже после повторного переключения флажка. Отключённая категория уведомлений учитывается. Сохранение игры, маркера и уведомления входит в одну транзакцию.

## Проверки

- Django: 165 тестов, 160 пройдено; 5 проверок блокировок SQL Server пропущены на SQLite.
- React/JavaScript: 68 тестов, ESLint и production-сборка пройдены.
- Сквозная проверка настоящего React с Django использует отдельную временную БД. Проверены заполнение формы и её очистка, отсутствие реквизитов в запросе, один перевод при двойном нажатии, галерея, требования, история и очистка, поиск и закрепления обоих участников, уведомление о релизе после изменения через API администратора. Ранее проверявшиеся покупки, бесплатные игры и разделы также проходят.
- Новые серверные тесты проверяют изоляцию истории, лимиты, права на закрепления, синхронизацию с исходным сообщением, сохранение правок каталога, подарки/возвраты, настройки уведомлений, повторную доставку и откат при ошибке.
- В браузере проверены галерея и её увеличение, таблица требований, пополнение произвольными тестовыми значениями с очисткой формы и закрепление сообщения. Все действия выполнялись на временных аккаунтах и отдельной БД. Тестовый сервер использует отдельное имя session-cookie, чтобы открытая тестовая вкладка не мешала входу в основной магазин.
- SQL Server и Docker в этой проверке не запускались. Настоящих платежей и игровых лицензий нет.

## Обновление

После резервного копирования базы и медиа выполнить `manage.py migrate`, затем `manage.py seed_catalog` и перезапустить серверы. Существующие аккаунты, кошельки, заказы и переписки сохраняются. Новые таблицы не требуют переноса старых сообщений.

Галерея и требования редактируются в форме игры в Django Admin. Смена статуса релиза выполняется сохранением формы/API, а не массовым SQL-обновлением. Уведомления приходят внутри магазина при следующем обновлении состояния клиента. Поиск в чате фильтрует уже загруженную историю; для большого объёма переписки понадобятся пагинация и отдельный поисковый endpoint.
