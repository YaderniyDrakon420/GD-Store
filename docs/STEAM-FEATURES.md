# Профиль, сообщество, экономика и защита аккаунта

## Обновление

Из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
.\.venv\Scripts\python.exe backend\manage.py migrate
.\.venv\Scripts\python.exe backend\manage.py sync_achievements
.\.venv\Scripts\python.exe backend\manage.py seed_store_products
```

Перезапустите Django и Vite. После обновления может потребоваться повторный вход: сервер теперь использует общий обработчик двухфакторной аутентификации. База, игры и покупки сохраняются. Перед миграциями сохраните резервную копию базы и каталогов загрузок.

`sync_achievements` учитывает существующие покупки, отзывы, дружбу и публикации. Повторный запуск не выдаёт награды повторно. `seed_store_products` добавляет три явно подписанных учебных примера и сохраняет изменения администратора. Команда требует существующих GTA V и CS2 из `seed_catalog`.

## Где что находится

| Раздел | Как проверить |
| --- | --- |
| Библиотека → Достижения (`/progress`) | Посмотреть XP и условия восьми значков; выбрать полученный значок для профиля. Каждые 200 XP повышают уровень. |
| Библиотека → Инвентарь (`/inventory`) | За каждый значок выдаётся уникальная карточка. Предложить другу предметы, войти другом, проверить состав и подтвердить обмен. |
| Инвентарь → Торговая площадка | Выставить карточку, купить вторым аккаунтом с учебного кошелька. Проверить предмет и записи кошельков у обоих участников. |
| Сообщество → Центры игр (`/hub`) | Новости публикует администратор; руководства и скриншоты — игроки. Доступны комментарии, лайки, редактирование автором и скрытие администратором. Здесь же находятся отзывы, обсуждения и мастерская. |
| Магазин → Рекомендации (`/discover`) | Сервер подбирает игры по жанрам и тегам библиотеки и желаемого. «Интересно» добавляет игру в желаемое; «Не интересно» убирает из очереди. Ответы можно сбросить. |
| Магазин → Издания и комплекты (`/products`) | Администратор создаёт издания, DLC и наборы. Перед покупкой сервер показывает итоговую цену. DLC требует выпущенную основную игру. |
| Библиотека | Дополнения находятся в блоке «Мои издания и дополнения». Текстовое содержимое доступно владельцу. Возврат — в истории заказов. |
| Друзья → Переписка | Видно «печатает…» и «Прочитано». Можно отправить изображение, PDF, TXT или ZIP до 5 МБ. |
| Меню профиля → Защита аккаунта (`/security`) | Подтвердить почту, включить TOTP, сохранить восемь резервных кодов, завершить другие сеансы. |

### Учебный режим

Карточки принадлежат GD Store, обмен не связан с инвентарём Steam. Платежи и площадка работают только при `PAYMENT_TEST_MODE=1`; реальные деньги не принимаются. Игровые достижения GTA/Valve не выдумываются: значки выдаются за подтверждённые сервером действия в GD Store.

Пример DLC — текстовая памятка GD Store в библиотеке, явно обозначенная как учебная. Это не официальный DLC, не игровой ключ и не установочный файл. Настоящая установка игр, облачные сохранения и игровой прогресс требуют отдельного клиента и интеграций с играми; они не входят в эти семь функций.

## Почта локально и на хосте

Локально Django сохраняет письма в **`backend/local_emails`**. Откройте созданный файл и перейдите по ссылке. Папка исключена из Git и не публикуется через HTTP.

Для настоящей доставки на хосте задайте:

```dotenv
FRONTEND_URL=https://store.example.com
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=smtp.example.com
EMAIL_PORT=587
EMAIL_HOST_USER=your-mail-user
EMAIL_HOST_PASSWORD=your-mail-password
EMAIL_USE_TLS=1
EMAIL_USE_SSL=0
DEFAULT_FROM_EMAIL=GD Store <noreply@example.com>
```

SMTP-данные предоставляет почтовый сервис. Для порта 465 обычно нужны `EMAIL_USE_TLS=0` и `EMAIL_USE_SSL=1`; не включайте оба режима одновременно. Без настроенного SMTP сервер на хосте не сможет доставлять настоящие письма. `FRONTEND_URL` указывает на фронтенд: письма открывают `/account-action`.

Ссылки одноразовые, действуют 30 минут. Сервер хранит только хеш токена. Восстановление пароля не отключает 2FA: нужен код приложения либо резервный код. Прежний регистрационный код восстановления сохранён; при включённой 2FA он также требует второй фактор.

## Защита аккаунта

- TOTP совместим с приложениями-аутентификаторами: ручной ввод ключа или `otpauth`-ссылка. Код состоит из 6 цифр и меняется раз в 30 секунд. Допускается один соседний временной интервал. Принятый код нельзя использовать повторно.
- Секрет зашифрован Fernet ключом, производным от `DJANGO_SECRET_KEY`; резервные коды хранятся в виде хешей. На хосте используйте постоянный сильный ключ и сохраните его вместе с защищёнными резервными копиями. Его потеря делает расшифровку TOTP невозможной.
- Второй фактор проверяется при входе с фронтенда, через прежний JWT API и в Django Admin. Включение 2FA завершает остальные браузерные сеансы и отзывает прежние JWT, включая refresh-токены.
- Список сеансов показывает браузер и ОС, не раскрывая ключи сессий. Завершение отдельного сеанса действует сразу; «Завершить остальные» также отзывает JWT. В текущем браузере вход сохраняется.
- Чувствительные действия требуют текущий пароль и второй фактор, если он включён. Вход ограничен общей для всех процессов записью базы: 10 попыток на аккаунт в минуту. Дополнительно действуют ограничения API по IP/пользователю.

## Правила данных

- Обмен действует 7 дней и требует согласия получателя. Исходящие предметы резервируются. Смена владельца, блокировка друга и попытки одновременно продать предмет проверяются сервером.
- Списание, зачисление и смена владельца выполняются одной транзакцией. Повтор запроса не создаёт вторую покупку.
- Награды конечные: продажа карточки, возврат игры или удаление публикации не позволяют получить тот же значок повторно.
- Комплект не создаёт повторную запись уже имеющейся игры. Итог учитывает недостающие игры пропорционально их текущей цене; владение бесплатной игрой не удешевляет платную. Для полностью бесплатного состава используется доля количества недостающих игр.
- Возврат DLC удаляет лицензию и возвращает учебные средства. Основную игру нельзя вернуть, пока остаётся отдельно купленное DLC. Состав проданного товара менять нельзя — создайте новый товар.
- Вложения в переписке доступны участникам. Публикация скриншота в центре игры делает его общедоступным. Скрытие публикации закрывает публичный доступ, сохраняя доступ автора, модератора и участников переписки, если файл отправлялся в чат.
- Изображения проверяются и пересохраняются без исходных метаданных. Другие вложения скачиваются и не исполняются сервером. Лимит вложений — 100 МБ на пользователя; хранилище мастерской учитывается отдельно.
- Чат обновляется примерно раз в 5 секунд. «Печатает…» истекает через 8 секунд; прочтение отмечается только в видимом активном диалоге.
- Текущая архитектура снимка состояния рассчитана на небольшой учебный проект. Для большой аудитории потребуются API с пагинацией, общая очередь писем и WebSocket-уведомления.
