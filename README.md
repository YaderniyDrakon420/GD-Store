# GD Store

Учебный магазин на React и Django. Каталог, аккаунты, библиотека, кошелёк, друзья, чаты, мастерская, события, коллекции, поддержка и модерация работают через сервер. Дизайн сохранён; каталог содержит GTA V, учебный предзаказ GTA VI, Counter-Strike 2 и Dota 2.

[Итоги финальной проверки и изменения](docs/FINAL-AUDIT.md).

## Быстрый запуск: Windows / PowerShell

Нужны Python 3.12+, Node.js 22.12+ и Git. Команды выполняются из корня проекта.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
if (-not (Test-Path backend/.env)) { Copy-Item backend/.env.example backend/.env }
```

В `backend/.env` включите учебные платежи:

```dotenv
PAYMENT_TEST_MODE=1
```

Без этого переключателя сервер запрещает покупки и пополнение. Реального платёжного провайдера нет: тестовая карта, быстрый заказ и кошелёк используют только учебные суммы. Данные карты на сервер не отправляются.

```powershell
.\.venv\Scripts\python.exe backend/manage.py migrate
.\.venv\Scripts\python.exe backend/manage.py seed_catalog
.\.venv\Scripts\python.exe backend/manage.py createsuperuser
.\.venv\Scripts\python.exe backend/manage.py runserver 127.0.0.1:8000
```

В другом терминале:

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

Откройте **http://127.0.0.1:5173**. Зарегистрируйте обычный аккаунт через сайт. Администратор входит с учётной записью, созданной командой `createsuperuser`. Готовых аккаунтов и стандартных паролей нет.

Для macOS/Linux используйте `python3 -m venv .venv`, `.venv/bin/python` вместо Windows-пути и `npm` вместо `npm.cmd`.

## Что проверить

1. Войти, пополнить учебный кошелёк, купить игру с PLAY10. Убедиться, что баланс, заказ и библиотека сохраняются после перезагрузки.
2. Во втором браузере или приватном окне создать другого пользователя. Отправить заявку, принять её и обменяться сообщениями. Обновление между клиентами — примерно раз в 5 секунд.
3. Создать обсуждение и ответ, написать отзыв на купленную игру и оценить чужой отзыв.
4. Добавить работу в мастерскую с настоящим ZIP-файлом до 10 МБ, подписаться и скачать архив другим аккаунтом.
5. Создать событие с приглашением друга, команду и сообщение в командном чате; собрать коллекцию из купленных игр.
6. Создать обращение в поддержку. Под администратором ответить, изменить статус и рассмотреть жалобу. Назначать других администраторов может только суперпользователь.
7. Отключить видимость библиотеки и проверить профиль из другого аккаунта. Чужие кошельки, заказы и личные переписки сервер не отдаёт.

При регистрации показывается ключ восстановления. Сохраните его отдельно: почтовой отправки нет. Пароль можно восстановить по логину и этому ключу. Смена пароля делает старые сессии недействительными.

## Хранение и администрирование

По умолчанию используется SQLite: `backend/db.sqlite3`. Обложки и аватары Django находятся в `backend/media`, ZIP-файлы мастерской — в `backend/private_uploads`. Эти данные и `.env` исключены из Git. Резервная копия должна включать базу и оба каталога файлов.

Админка Django: **http://127.0.0.1:8000/admin/** → **Catalog → Games**. В ней можно изменять названия, описания, обложки, платформы, дату релиза, цены, скидки и флажки `Is published` / `Предзаказ`. Рейтинги считаются по реальным отзывам пользователей этого магазина. Смена цены или условий предзаказа после расчёта заказа требует повторного подтверждения покупателем.

`seed_catalog` добавляет GTA V (версия Enhanced для ПК, учебная цена 599 ₴), GTA VI (учебный предзаказ за 2999 ₴), бесплатные Counter-Strike 2 и Dota 2, а также промокод PLAY10. Это учебные суммы, а не предложение купить лицензию по указанной цене. Повторный запуск сохраняет изменения администратора. Шесть прежних демоигр снимаются с публикации, а их записи, покупки и история сохраняются. Дополнительные игры, созданные администратором, команда не удаляет.

Оплаченный учебный предзаказ хранится в библиотеке с пометкой ожидания; он также фиксируется в строке заказа. Отзыв до релиза запрещён сервером. После фактического выхода игры администратор снимает флажок `Предзаказ`: библиотека начинает показывать обычную запись, а история сохраняет факт предзаказа. Автоматического включения по календарной дате нет. Выдачи настоящих ключей и лицензий нет ни до, ни после релиза.

Баллы начисляются за покупки: целая часть суммы заказа / 10. Пополнения кошелька и бесплатные игры баллов не дают. Бесплатные игры оформляются при нулевом балансе без записей о списании. Возврат учебного заказа удаляет его игры из библиотеки получателя, возвращает списанный демокошелёк и отменяет начисленные баллы. Если баллы уже потрачены, нужен разбор через поддержку.

Для пополнения кошелька выберите сумму и заполните номер тестовой карты, имя, срок действия и CVC. Подойдут любые непустые значения: проверки номера, срока и CVC нет. После подтверждения сервер начисляет учебную сумму. Реквизиты остаются только в памяти формы, не отправляются и очищаются после успешного пополнения. Настоящие данные карты не нужны. Сервер по-прежнему требует вход, включённый учебный режим и целую сумму от 1 до 10000 ₴; повторное нажатие не создаёт второе пополнение.

Файлы мастерской не распаковываются и не запускаются на сервере. Скачивание требует входа; скрытые работы доступны только автору и модератору. Лимит хранилища — 100 МБ на аккаунт. Автоматической установки модов или игрового клиента здесь нет. Интеграции с игровым прогрессом Steam/консолей нет, поэтому достижения не выдумываются.

## Дополнения магазина и чатов

**Онлайн/оффлайн теперь определяется сервером.** Сайт обновляет индикаторы примерно раз в 5 секунд; сессия без связи перестаёт считаться онлайн через 90 секунд от последнего сохранённого подтверждения. Выход из аккаунта завершает присутствие этой сессии сразу, другие устройства остаются онлайн. В профиле доступны «Автоматически», «Невидимый» и ручное «В игре». Старая настройка «Не в сети» сохраняется как «Невидимый»; для автоматического статуса выберите «Автоматически».

Фронт и Django можно разместить на разных хостах. Адрес API задаётся через `VITE_API_BASE_URL` перед сборкой. Для несвязанных доменов предпочтителен прокси `/api` и `/media` на стороне фронта. Подробные настройки, ограничения cookies и порядок проверки: [docs/SPLIT-HOSTING.md](docs/SPLIT-HOSTING.md).

- **Скриншоты и требования.** На странице игры работают миниатюры, стрелки и увеличение изображения. У GTA V Enhanced, CS2 и Dota 2 загружаются по три официальных скриншота и минимальные требования к Windows. Источники указаны в `game-asset-sources.json` и `backend/apps/studio/catalog_details.json`. Для GTA VI требования к ПК и скриншоты не выдумываются: пока они не добавлены, показано пустое состояние.
- **Недавно просмотренные.** После входа сервер сохраняет последние 12 игр; повторный просмотр перемещает игру в начало. Раздел находится внизу каталога. Кнопка «Очистить историю» удаляет список аккаунта. Через API чужая история не возвращается, неопубликованные игры скрываются.
- **Поиск и закрепления в чате.** Поиск фильтрует загруженную с сервера переписку без учёта регистра. Каждый участник может закрепить или открепить сообщение, пока собеседники остаются друзьями. До 10 закреплений на диалог; они сохраняются на сервере и видны обоим участникам. Фильтр «Закреплённые» совместим с поиском.
- **Выход предзаказа.** Когда администратор сохраняет опубликованную игру со снятым флажком «Предзаказ», её текущие владельцы, оплатившие предзаказ, получают одно внутреннее уведомление. Для подарка получателем будет владелец подарка. Возвращённые заказы и обычные покупки не участвуют. Повторное сохранение не дублирует уведомление. Категория «Выход предзаказанных игр» отключается в настройках; пропущенные уведомления задним числом не рассылаются.

Редактировать галерею можно в **Catalog → Games → нужная игра → Screenshots**: загрузите изображения и задайте `Order`. Ниже расположен блок **System requirement** с характеристиками и дополнительными требованиями. `seed_catalog` заполняет только отсутствующие требования и пустую галерею, сохраняя ручные правки. Если удалить галерею целиком и снова запустить эту команду, исходные изображения добавятся заново.

Изменять статус релиза следует обычным сохранением в админке или API каталога. Массовый `QuerySet.update()` и ручной SQL обходят обработчик уведомлений. Дата сама по себе не переводит игру в обычную продажу. Это уведомление внутри GD Store, без отправки почты и выдачи игровой лицензии.

## Обновление уже установленной версии

Остановите сервер и сделайте резервную копию `backend/db.sqlite3`, `backend/media` и `backend/private_uploads`. Сохраните свой `.env`. Затем из корня проекта:

```powershell
.\.venv\Scripts\python.exe backend/manage.py migrate
.\.venv\Scripts\python.exe backend/manage.py seed_catalog
```

Перезапустите Django и Vite. Нужно выполнить обе команды: миграции добавляют поля предзаказа, примечания к требованиям и таблицы закреплений/уведомлений о релизе, а `seed_catalog` обновляет витрину и добавляет недостающие галереи и требования. Исходные изображения находятся в `frontend/public/art`, их происхождение записано в `game-asset-sources.json`.

## SQL Server

Поддержка `mssql-django` сохранена. Для использования SQL Server создайте базу `gdstore`, установите ODBC Driver 18 и настройте `DB_ENGINE=mssql`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT` в `backend/.env`. Затем выполните миграции и загрузку каталога теми же командами.

Существующий `.env` не перезаписывайте: если в нём уже есть `DB_HOST`, `DB_USER` или `DB_NAME`, отсутствие нового `DB_ENGINE` сохраняет прежний выбор SQL Server. Для перехода на SQLite укажите `DB_ENGINE=sqlite` явно. Для учебной оплаты в существующий `.env` нужно добавить `PAYMENT_TEST_MODE=1`.

При обновлении существующей версии миграция `studio.0003_existing_chat_history` сохраняет переписки из прежнего приложения `chat` в представлении нового интерфейса. Оба API продолжают использовать общие сообщения; автор существующей блокировки, аватар и страна профиля сохраняются. Команда `seed_catalog` теперь единая для старого и нового входа и не меняет установленные вами цены.

SQLite подходит для учебного запуска. Проверки блокировок SQL Server нужно запускать отдельно на тестовом SQL Server: `python manage.py test` из `backend` с `PAYMENT_TEST_MODE=1`. У пользователя БД должны быть права на создание тестовой базы. Не запускайте это с реквизитами рабочей базы.

## Docker для локального запуска

После копирования и настройки `backend/.env`:

```powershell
docker compose up --build
```

Магазин: **http://localhost:5173**. Создание администратора:

```powershell
docker compose exec backend python manage.py createsuperuser
```

Этот Compose использует SQLite и сохраняет базу, мастерскую и медиа в именованных томах. Он предназначен для локальной разработки. Docker и SQL Server в среде подготовки патчей не запускались; проверен прямой запуск Python + Node на Windows.

## Проверки

```powershell
cd backend
..\.venv\Scripts\python.exe manage.py check
..\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
..\.venv\Scripts\python.exe manage.py test --settings=config.test_settings --noinput
cd ../frontend
npm.cmd test
npm.cmd run lint
npm.cmd run build
```

Сквозная проверка React с настоящим Django использует отдельную временную SQLite-базу. Из папки `frontend`:

```powershell
$env:PYTHON = (Resolve-Path ../.venv/Scripts/python.exe).Path
npm.cmd run test:integration
npm.cmd run test:integration:split
```

Она проверяет загрузку 20 основных разделов, форму пополнения с передачей только суммы и защитой от двойного клика, сохранение корзины, покупку из учебного кошелька, оформление двух бесплатных игр, предзаказ и его отображение в библиотеке/заказах, запрет преждевременного отзыва, галерею и требования, личную историю просмотров, поиск и общие закрепления в чате, а также уведомление после смены статуса релиза через API администратора. Рабочая база и пользовательские файлы в этой проверке не используются.

Тестовые настройки используют отдельную SQLite-базу и быстрый хешер паролей **только для тестов**. Не используйте `config.test_settings` для работающего сервера. CI выполняет эти проверки автоматически.

## Архитектура и API

- `apps.accounts/catalog/store/library/reviews/payments` остаются источником данных для аккаунтов, каталога и покупок.
- `apps.studio` хранит профили, настройки, документы сообщества, файлы, журналы баланса и ключи повторных запросов.
- `GET /api/v1/studio/snapshot/` возвращает каталог и доступные текущему пользователю данные. Приватность проверяется до формирования ответа.
- `POST /api/v1/studio/account/` — вход, регистрация, выход и восстановление; защищён CSRF.
- `POST /api/v1/studio/commands/` — проверенные сервером действия. Нужен UUID в `Idempotency-Key`.
- `POST /api/v1/studio/quote/` — подписанный расчёт покупки, действительный 10 минут. Сервер повторно проверяет цену, владельца, получателя, промокод, статус предзаказа, дату релиза и платформу при покупке.
- `POST /api/v1/studio/uploads/`, `GET /api/v1/studio/mods/<id>/download/` — файлы мастерской.
- Предыдущие API v1 остаются доступны. Endpoint создания старой попытки оплаты больше не возвращает фиктивный платёжный URL; новый интерфейс оформляет покупку через studio checkout.

Фронтенд использует HttpOnly-сессию Django и CSRF-токен. Vite проксирует `/api` и `/media` на Django. Старые модули `src/demo` сохранены как тестовые примеры и вспомогательные функции; данные пользователей через localStorage больше не сохраняются. Автоматического переноса старых локальных демопрофилей нет: это были общие вымышленные пользователи без серверного подтверждения личности.

Снимок состояния и общая блокировка изменений выбраны для небольшого учебного проекта. Для большого количества пользователей потребуются постраничные выборки, отдельные таблицы/потоки сообщений и общий кеш ограничений запросов. Перед публикацией отдельно настройте HTTPS, секрет, `DJANGO_DEBUG=0`, допустимые хосты, проксирование API, резервные копии и статические файлы. Настоящие платежи в этот проект не входят.
